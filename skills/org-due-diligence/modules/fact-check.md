# Fact-check (independent skeptic)

Run this on every Org Dossier and Decision Brief before the user sees it.

If your platform supports subagents, run it as a separate agent. Give that agent only the draft plus `references/confidence-and-traps.md` and `references/guardrails.md`, not the conversation. Independence is the point: an early version of this skill presented a headcount comparison inflated by contractor networks, and a second reader would have caught it.

## Checklist

**Every number**
- What does it actually measure: employees, or everyone who lists the company? One function, or all of them? (traps 1–2)
- Is the base shown next to any growth rate? (trap 3)
- Is there a source and a date? Is anything older than 12 months flagged? (trap 10)

**Every claim that drives a rating**
- Is the label right? Crowd-sourced org charts and self-reported titles are never "Verified". (traps 4–5)
- Postings: is "removed" being read as "filled", or a location-specific band treated as universal? (trap 6)
- Valuation: is the last round being treated as today's value? (trap 7)
- Is a review-site theme being used as a headline? (trap 8)
- Could this be a different person with the same name? (trap 9)

**Every rating**
- Does the cited evidence actually support it? Would a skeptic give the same rating?
- Is a guess hiding what should be a "?"?

**Nuance (the skeptic also checks for emptiness)**
- Does the bottom line answer the user's *real* question and name the catch?
- Is every table followed by what it tells you?
- Is every caveat paired with a question to ask?
- Would any sentence fit any company? Make it specific or cut it.
- For a Decision Brief: is there an honest reframe, a section going option by option, the money with its caveats, coaching for the conversations that matter, and a dated two-week plan?

**Guardrails**
- Remove anything about someone's personal life, family, health, age, or other protected characteristics.
- Rewrite any character judgment based on thin evidence as a pattern or a question.
- Check the output stays within its length cap.

## Output

Produce a short list of issue → fix pairs, apply the fixes, then deliver.

Don't show this checklist to the user unless they ask. Do mention any correction that changed a rating, because that's useful for them to know.
